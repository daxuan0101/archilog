# 아키로그 콘텐츠 정리 및 이관 계획

## 목표 포지션

> 금융권 고객 채널에서 앱과 웹의 경계를 고민하고, 안정적인 웹서비스 구조를 만들어가는 개발자

글의 수보다 독자가 대표 글을 따라 읽으며 다음 흐름을 이해할 수 있도록 구성한다.

`채널 개발자의 역할 → 앱과 웹의 경계 → 인증과 검증 → 웹플랫폼 전환 → 협업과 운영`

## 운영 기준

- 티스토리 원문을 그대로 복사하지 않고 현재의 아키로그 문체로 재작성한다.
- 실제 업무에서 고민이 시작된 장면을 글 앞부분에 배치한다.
- 선택한 기술보다 판단의 이유와 현실적인 제약을 보여준다.
- 회사명, 프로젝트명, 시스템명과 구체적인 내부 수치는 공개 전에 제거한다.
- 모든 글은 Draft PR에서 공개 범위와 문장 흐름을 검수한다.
- 기존 작성일은 `date`, 재정리한 날짜는 `updated`로 관리한다.
- 이관이 완료되고 백업을 검증한 뒤 티스토리를 삭제한다.

## 우선 발행할 대표 글

1. 코드 너머의 채널 개발자
2. 앱 안에서 웹서비스를 자연스럽게 제공하려면 무엇을 먼저 정해야 할까
3. 하이브리드 앱에서 Native Bridge 사용 기준에 대한 고민
4. GNB는 앱 영역인가, 웹 영역인가
5. WebView의 전자서명은 어디까지 믿을 수 있을까
6. JSP 레거시 전환은 화면을 바꾸는 일이 아니었다
7. 작은 문구 수정은 왜 CMS에 대한 고민으로 이어졌을까
8. 디자인 시스템은 도구가 아니라 협업 기준입니다
9. 금융권 개발망에서 오픈소스와 개발 생산성을 함께 고민하는 법
10. 원장 메시지는 왜 그대로 고객에게 보여주기 어려울까

## 이관 작업 단위

1. 티스토리 원문과 이미지 확보
2. `content/articles.yml`에서 글 상태를 `draft`로 변경
3. 실제 장면, 처음의 생각, 질문, 선택 기준, 달라진 관점을 추출
4. 공개 불가능한 정보 제거
5. Markdown 초안 작성
6. 제목, 부제목, 카테고리, 태그 확정
7. Draft PR 생성
8. 모바일 문단, 이미지, 링크 검수
9. `main` 병합 및 Pages 확인
10. 관리표 상태를 `published`로 변경

## 상태 정의

| 상태 | 의미 |
|---|---|
| `published` | GitHub Pages 발행 및 검수 완료 |
| `draft` | 초안 작성 또는 Draft PR 진행 중 |
| `source-needed` | 티스토리 원문과 이미지 확보 필요 |
| `planned` | 신규 작성 또는 후속 글 예정 |
| `excluded` | 중복, 공개 위험 또는 방향성 불일치로 제외 |

- D-01 `금융권 개발망에서 오픈소스와 개발 생산성을 함께 고민하는 법`: 원문과 이미지 확보

## 티스토리 삭제 조건

- 이관 대상 글과 이미지의 별도 백업 완료
- 대표 글 10편 발행 완료
- 내부 링크와 이미지가 티스토리 주소에 의존하지 않음
- 개인 도메인, HTTPS, 사이트맵 확인 완료
- LinkedIn과 프로필의 주요 티스토리 링크 교체 완료
- PC와 모바일에서 전체 글 최종 검수 완료
